The project

The subject is personal finance. The useful part is the system behind it.

Budgeting App started as a way to bring accounts, income, expenses, savings and budgets into one structured application.

But the same problem appears constantly inside small businesses: information begins in spreadsheets, notes and disconnected tools. As the amount of data grows, simple tasks become harder to track and the business loses visibility over its own workflow.

That makes this project useful beyond budgeting. It demonstrates the foundation of a small internal business tool.

01

The problem

Information becomes difficult to use when it lives in too many places.

Accounts, transactions, savings and monthly budgets all represent related information, but managing each separately makes the full picture difficult to understand.

The challenge was to create one consistent system rather than a collection of disconnected screens.

02

The goal

Build a real application workflow, not just a dashboard mockup.

  • Create secure user accounts
  • Store structured records in a database
  • Add, update and delete financial records
  • Separate planning from daily activity
  • Make historical information searchable
  • Turn stored data into useful overview screens
03

The solution

A connected Flask application with database-backed workflows.

The application combines authentication, data entry, budgets, transaction management, savings and reporting in one interface.

Each feature contributes to the same workflow rather than operating as an isolated page.

A deliberate decision

A dashboard is only useful if the data behind it can actually be managed.

It would have been easy to focus mainly on charts and visual summaries. But dashboards become valuable only when the underlying workflow is reliable.

Users therefore need to be able to create records, correct mistakes, edit information, remove entries and review history.

Chosen approach Capture → organise → review → update → understand

That is the same principle I would apply to a business admin tool, CRM, booking system or operational dashboard.

The interface is built around actions rather than isolated screens.

What was built

The pieces behind a usable internal tool.

The project combines several common business-software patterns inside one application.

01

Authentication

Users register and sign in before accessing their own financial records and application data.

02

Structured database

Information is stored as organised records instead of relying on disconnected files or temporary page state.

03

CRUD workflows

Records can be created, reviewed, updated and removed as the underlying information changes.

04

Budget planning

Budget configuration is separated from daily transaction entry, creating a clearer planning workflow.

05

History & filtering

Transaction records can be reviewed and organised instead of disappearing into an unstructured list.

06

Dashboard views

Stored information is brought together into summaries that are easier to scan and understand.

Supporting workflows

The dashboard is supported by the smaller actions around it.

Beyond budgeting

The same foundation can support real business operations.

Replace transactions with bookings, customers, jobs, stock, enquiries or service records and the underlying problem is remarkably similar.

Data needs to be captured consistently, stored safely, changed when necessary and presented in a way that helps someone do their job.

Client management Booking dashboards Lead pipelines Inventory records Job tracking Reporting tools

Project principle

Good internal software turns repeated actions into a predictable workflow.

A useful dashboard is not just a collection of charts. It is the visible part of a system that helps people capture, organise, change and understand the information they work with every day.
